# 安全策略

[English](../../SECURITY.md) | [简体中文](SECURITY.md)

## 支持范围

安全修复在默认分支开发，随下一版发布。维护者会评估最新发布版本是否也需要这些修复。

| 版本 | 支持状态 |
|---|---|
| 默认分支 | 支持 |
| 最新发布版本 | 支持 |
| 更早版本 | 不提供常规维护 |

## 报告安全漏洞

不要通过公开 Issue、Pull Request、讨论区或日志附件披露疑似漏洞。

如果代码托管平台提供私密漏洞报告功能，请优先使用该入口。没有私密入口时，请发送邮件至 [menglingao@xiaomi.com](mailto:menglingao@xiaomi.com)，主题为 `[BSWorld Security]`。

请在报告中提供以下信息。

- 受影响的版本、提交和组件
- 安全影响以及攻击成立所需的条件
- 可复现的步骤或最小验证程序
- 相关配置和脱敏后的日志
- 已知的缓解建议

发送前请移除凭据、个人信息和无关的专有数据。如果报告必须携带敏感附件，请先联系维护者协商合适的私密传输方式。

维护者会确认收到报告，调查影响范围，协调修复，并与报告者商定公开时间。项目会在资源允许的情况下尽快处理。响应和修复时间没有固定承诺。

报告者愿意公开身份且情况适合时，可以在安全公告或发布说明中致谢。

## 策略适用范围

本策略覆盖 BSWorld 自有源码、测试编排、Docker 构建环境和项目发布的产物。

BabbleSim、Zephyr、NuttX、Linux 或其他上游依赖自身的漏洞，通常应报告给对应项目。如果漏洞由 BSWorld 的集成、打包或配置引入，或者暂时无法判断归属，可以先向 BSWorld 报告。

不涉及安全影响的普通功能缺陷，请通过公开 Issue 跟踪。

## 协调披露

公开漏洞前，请为问题复现、修复以及受影响发布产物的更新预留时间。维护者会向报告者同步进展，并在用户需要采取措施时发布安全公告。
